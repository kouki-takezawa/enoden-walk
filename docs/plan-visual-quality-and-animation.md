## 1. 確立している事実(再調査不要)

- `world.glb` / `character.glb` / `train.glb` は**画像テクスチャが0枚**(`images: null`)。色は頂点カラー+ランタイムのプロシージャルノイズ(`src/fx.js`)のみで作っている。これが「安っぽく見える」最大の原因。
- 三角形数(Draco展開後の概算): world 約48万、character 約22万、train 約5.7万。
- キャラクターに**ブレンドシェイプ(モーフターゲット)は無い**。表情・瞬きはBlender側でシェイプキーを作らない限り不可能。
- キャラクターのボーン(56本、標準的なヒューマノイド構成)には以下が含まれる: `LeftFoot` `RightFoot` `LeftToe` `RightToe` `Head` `Neck` `LeftEye` `RightEye` `Hips` `Spine` `Spine1` `Spine2` `LeftArm` `RightArm` など。→ 足IK・視線追従・呼吸・旋回リーンはコードだけで実装できる。
- アニメーションクリップは `Idle` `Walk` `Run` `Sprint` `Jump` の5つのみ(その場旋回・待機バリエーション・電車待ち仕草のクリップは無い)。
- `train.glb` は1ノード([`Enoden_1000_TwoCar`)に12プリミティブが結合されている。**車輪だけを独立して回すには、Blender側でノードを分離して再エクスポートする必要がある**(コードだけでは不可)。
- 共有uniformは `src/fx.js` の `export const U` にまとまっている(`uTime` `uNight` `uGust` `uWet` `uCloudSh` `uGlit` `uSunView` `uSunCol`)。新しいuniformもここに足す。
- 描画パイプラインは `src/render.js` の `Renderer` クラス(`EffectComposer` + bloom + `src/atmos.js` のカスタムパス)。画質プリセットは `src/config.js` の `PRESETS`(`low` / `medium` / `high`)。`autoPreset()` が低スペック端末を `low` に判定する。
- 現在の開発機には **Blenderは未インストール**、`npm install` は社内プロキシ等の制約で実質使えない(`pip` / `gh` / `vercel` は動く)。別端末では状況が違う可能性があるので、Gate A/Bで都度判定する。
- Vercelのプレビューデプロイ(PRごとのURL)は**SSO保護があり外部から開けない**。本番は `https://enoden-walk.vercel.app`。
- 前回セッションで `tests/reach.test.js`(全名所・ホーム全域への到達性)と `tests/nav.test.js`(経路探索)を追加済み。同種のテストを再度作らない。

## 2. 方針・やらないこと

- **既存の `low` / `medium` / `high` プリセットの見た目と負荷は変えない**。新機能は新設定 `ultra` に載せるか、プリセットのフラグで各機能をON/OFFできるようにする(フラグが無ければ何も変わらない)。
  - 例外: 色収差・フィルムグレイン(4-3-3)とSMAA(4-3-2の下位互換部分)はコストがほぼ無いため全プリセット共通でよい。
- 酔い対策として、モーションブラー(4-3-5)と将来のカメラ振動系は**デフォルトOFF**、設定画面にトグルを置く。
- 1フェーズ = 1コミットを目安にする(レビューしやすく、途中で打ち切っても差分が壊れない)。
- 各フェーズの「検証」は**フェーズ単位でまとめて1回**行う(タスクごとに毎回スクリーンショットを撮らない)。

## 3. 実装順序の全体像(依存関係)

```
Phase C1(共有基盤) ─┬─→ Phase C2(マテリアル: 法線/ラフネス/視差)
                    ├─→ Phase C3(ポストプロセス一式)
                    └─→ Phase C4(キャラクターprocedural animation)
Phase C5(ワールド細部) ── 独立、いつでも着手可
Phase C6(反射拡張)    ── C2の後が望ましい(同じシェーダー領域を触るため)

[Blenderが使える場合]
Phase B1(テクスチャベイク) ── 着手するなら Phase C2 より前
Phase B2(キャラクター)     ── 独立
Phase B3(ジオメトリ)       ── 独立
Phase B4(ライティング等)   ── 独立
```

C1は他の全フェーズの土台なので必ず最初に終わらせる。C2〜C6・B1〜B4は互いにファイルの競合が少ないので、C1の後はどの順で進めてもよい(ただし表の「メモ」欄に依存がある場合は従う)。

## 6. 検証手段まとめ

- `npm run dev` / `npm test` が動く端末 → 通常どおりそれを使う。
- 動かない端末 → `tools/devserver.py`(Vite無しの簡易配信) + `tools/screenshot.py`(ヘッドレスブラウザでスクショ+コンソールエラー取得)。使い方は `tools/README.md`。`window.__enoden` 経由で瞬間移動・時刻変更・画質切替・シミュレーション単独実行ができる。
- Vercelプレビューデプロイ(PRのURL)はSSO保護で外部から開けないので、確認には使わない。マージ後の本番 `https://enoden-walk.vercel.app` か、ローカル確認手段を使う。
